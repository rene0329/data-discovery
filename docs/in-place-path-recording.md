# 原位计算任务路径时延记录

原位计算任务在选择计算节点前，为每个可用源副本与每个可调度计算节点记录一条 `PLACEMENT_PATH` 事件，持久化至 `task_execution_event`。记录范围包含中心节点、资源不足的候选节点，以及因其他候选累计时延更低而未被选中的节点。

事件沿用 `sourceNode`、`targetNode`、`replicaId`、`latencyMs`、`bandwidthMbps`、`pathNodeIds` 和资源检查字段。路径使用调度时网络拓扑中有效的链路测量计算，路径时延为沿途链路时延之和；不是重新执行网络探测，也不在任务运行中持续采样。

- 有有效路径：`outcome=RECORDED`。
- 无有效测量路径：`outcome=UNAVAILABLE`，路径时延、带宽及节点序列为空，不填估计值。
- 源节点就是计算节点：时延为 0，路径仅含该节点；带宽沿用拓扑本地路径的无限带宽标记 `Long.MAX_VALUE`。

节点选择采用多源 Dijkstra 最短路径算法，以所有可用副本为源，按累计时延选择资源满足当前作业需求的计算节点；`tier` 仅描述本地、同站点或跨站点关系，不决定优先级。`PLACEMENT_CANDIDATE` 按实际候选顺序记录每个计算节点的最近源副本，`PLACEMENT_SELECTED` 记录最终分配。新增记录不因提前选中节点而缺失，也不将全部记录的路径当作已经参与排序的候选。不可用副本和不可调度节点仍由原有可用性检查排除。

历史任务不补写路径记录；新版本生效后新提交的原位计算任务产生完整记录。
