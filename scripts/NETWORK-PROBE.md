# 手动测量全部配置链路

在本机终端执行：

```bash
ssh ZJ 'python3 -u /data/topic4-build/repos/data-discovery/scripts/network-probe-now.py'
```

脚本使用 Python 3 标准库和构建主机的 kubectl。它读取线上 network-probe
DaemonSet 的链路、内网地址、探测时长和中央服务配置，自动查找当前就绪的探测
Pod，逐条执行 10 次 ping（间隔 1 秒，单次等待 2 秒，总限时 20 秒）和正反向各 2 秒的 iperf3（时长以线上配置为准）。
终端显示执行节点、目标 IP、实际 ping 命令、开始时间、原始逐次响应和汇总统计。
原始统计包含发包数、收包数、丢包率以及 RTT 最小值、平均值、最大值和 mdev。
延迟取成功响应的平均 RTT；部分丢包时仍保留有效平均值，并在原始统计中展示丢包。
未取得有效 RTT 时不会记为零。终端不输出带宽数值；后端仍接收原有带宽指标，
带宽取两个有效方向中的较小值；只有一个方向有效时沿用该值，
与自动探测的带宽汇总规则一致。每日自动探测仍使用原来的 4 次 ping；
手动 10 次采样属于短时测量，不代表长期延迟分布。结果立即提交现有指标接口，用于更新系统中的链路指标。
测量失败会按现有规则上报不可用状态；控制请求或上报失败会显示失败。

脚本不修改 DaemonSet、不重启 Pod，也不改变每日自动探测的时间安排。新增或
替换 Pod 后无需修改命令。全部链路指线上配置的拓扑边，不包含任意节点对。
认证令牌从现有 Secret 读取，仅在内存中使用，不打印、不写入文件。

手动探测遵守现有带宽探测开关和业务传输保护。被禁用或正在传输的链路会显示
跳过，不覆盖旧指标。退出状态 0 表示全部成功；1 表示有跳过、失败或已有手动
探测在运行。执行过程中会短暂占用被测链路带宽，请等待最终汇总。

该脚本独立于定时任务运行；与自动探测偶遇时，iperf3 服务忙会按自动探测相同
策略进行有限重试。它不是业务传输的预约锁，业务保护检查与实际测量之间仍可能
有新的传输开始。

更新脚本遵循本地修改、测试、提交、推送，再由 ZJ 干净的构建仓库执行
`git pull --ff-only origin main`。此工具直接由主机 Python 运行，无需重建或
滚动更新应用镜像。
