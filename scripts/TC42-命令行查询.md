# TC-4.2 测试原始信息查询

`tc42-api.sh` 调用前端使用的后端接口，展示前五个用例所需的数据集、任务、温度、存储调度、访问权限及加速比原始记录。需要 Bash 和 Python 3，无第三方 Python 依赖。可从本机或能访问后端的 Linux shell 运行。

默认仅将 JSON 缩进以便阅读，保留完整的 `code`、`msg`、`data` 和字段值；`--raw` 原样输出响应字节。请求地址写入标准错误，响应写入标准输出。所有业务查询均为 GET，不创建任务、不更新温度、不迁移数据、不发放授权。

## 配置

在 data-discovery 仓库目录运行：

```bash
export TOPIC4_API_URL=http://10.15.16.40:30482
# 输入当前测试用户登录后的 Bearer 令牌（不含 Bearer 前缀）
read -r -s TOPIC4_TOKEN
export TOPIC4_TOKEN
./scripts/tc42-api.sh me
```

令牌使用前端登录所用的 `/api/v1/auth/login` 返回值；也可使用已有登录会话的令牌。不要把令牌写入脚本、报告或版本库。安全访问用例中，`access` 应使用 owner-a 的令牌；管理员查询审计和授权日志时切换为管理员令牌。`me` 可核对当前身份。不会自动切换或提升用户权限。

以下编号仅为文档中的历史示例；新一轮测试请替换为实际返回的编号。先用 `datasets`、`tasks`、`plans` 查找；分页接口默认只查第 1 页，每页 20 条，使用 `--page`、`--page-size`、`--query` 继续查询。

## 测试前统一检查

```bash
./scripts/tc42-api.sh datasets --page-size 100
./scripts/tc42-api.sh nodes --page-size 100
./scripts/tc42-api.sh topology
./scripts/tc42-api.sh replicas 1 4 6
```

数据集详情包含温度和登记状态，副本接口包含存储节点、可用性、文件路径及校验信息；拓扑内容以接口实际返回为准。节点链路实测记录及 Linux 文件状态可以继续用已有 `show-tc42-evidence.sh baseline`、`show-scheduling-evidence.sh` 核对。

## 用例 1 集中式计算

```bash
./scripts/tc42-api.sh tc1 228
```

输出完整任务及执行事件，供核对 executionMode、调度路径、实际节点、起止时间、传输字节数及校验值。`tc1` 是 `task` 的便捷名称，不筛掉其他模式；应检查查询任务是否确实为本轮集中式任务。

## 用例 2 分布式计算

```bash
./scripts/tc42-api.sh tasks --query ciao
./scripts/tc42-api.sh tc2 <本轮分布式任务ID>
```

与用例 1 使用相同任务详情接口，保留所有调度决策和执行事件，便于对照实际执行位置。

## 用例 3 温度感知和热敏制导存储

```bash
./scripts/tc42-api.sh datasets --query Tiny
./scripts/tc42-api.sh datasets --query CIFAR
./scripts/tc42-api.sh policy
./scripts/tc42-api.sh tc3 <Tiny数据集ID> <CIFAR数据集ID>
./scripts/tc42-api.sh reads <Tiny数据集ID>
./scripts/tc42-api.sh task 229
./scripts/tc42-api.sh plan 65
./scripts/tc42-api.sh replicas <Tiny数据集ID>
./scripts/tc42-api.sh task 230 244
```

在访问前、访问后、热度更新后、迁移后和停止访问后的观测时间点分别查询并保存结果。温度更新和迁移通过现有平台执行；查询不会触发它们。`reads` 默认只返回最近 100 条，可用 `--limit` 调整。计划详情展示后端登记状态；实际文件大小与 SHA-256 使用已有脚本核对，避免将登记记录等同于现场文件校验。

## 用例 4 安全访问

```bash
# owner-a 身份：授权前后分别查询
./scripts/tc42-api.sh me
./scripts/tc42-api.sh tc4
# 管理员身份：核对拒绝原因及短期授权发放记录
./scripts/tc42-api.sh audit --principal owner-a --decision DENIED --limit 100
./scripts/tc42-api.sh grants --limit 500
./scripts/tc42-api.sh task 232
```

这些命令展示已有记录。未授权任务提交、短期令牌申请及授权后的任务创建仍通过现有平台执行。审计查询可进一步使用 `--request-id` 或 `--run-id`，输出后按实际数据集和测试时间核对。

## 用例 5 数据移动加速比

```bash
./scripts/tc42-api.sh tc5 233 234 235 236 237 238 239 240
# 两种模式分开提交且共享 acceptanceRunId 时
./scripts/tc42-api.sh comparison <acceptanceRunId> --round 1
```

`tc5` 保留原始任务与逐数据集计时事件，不自动给出通过结论。特别注意历史字段命名：前端将任务字段 `t2` 作为大纲中的集中式时间 T1，将 `t1` 作为分布式时间 T2；单位为秒，`rating` 为加速比。执行事件的 `durationMs` 单位为毫秒。不要直接按字段名称把 t1 当成集中式时间。仅在两种模式完成、证据完整且分布式时间大于零时，才能复算集中式时间/分布式时间并判断是否大于 1.2。

已有 `show-tc42-evidence.sh speedup <任务ID...>` 可以查询数据库累计计时及逐数据集事件，交叉核对原始接口结果。

## 保存与退出码

```bash
./scripts/tc42-api.sh --raw task 233 > task-233.json 2> task-233-request.log
./scripts/tc42-api.sh task 233 | tee task-233-display.txt
```

保存单个完整 JSON 时每次只指定一个编号。多个编号会顺序输出多份响应，不合并为数组；`--raw` 不额外插入分隔符。默认缩进模式适合多编号终端展示。日志和响应可能包含敏感业务信息，请在受控目录保存。

退出码 0 表示所有查询 HTTP 成功且业务 code 为 0；1 表示至少一个网络、HTTP、业务或响应格式错误；2 表示参数错误。批量查询中一项失败后仍继续查询后续编号，最终返回 1。错误响应仍完整输出；查询成功不代表测试用例通过。

本地验证：`python3 -m unittest discover -s scripts/tests -p 'test_tc42_api.py'`。
