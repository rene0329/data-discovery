## 用例5 按前端创建任务的顺序查看

每次在前端创建对应类型的任务，拿到任务 ID 后，只查询这一个任务。单次输出按“执行日志 → 最终调度节点 → 计时与加速比”展示，并分别保存文件；不会校验或展示其他类型的任务，也不要求下一步任务已经创建。任务仍在运行时可以查询，完成后可用同一命令再次采集。

```bash
ssh ZJ
cd /data/topic4-build/repos/data-discovery

# 第一步：前端创建 ciao、epinions、yelp 多数据集对比任务，获得ID后
./scripts/tc42-case5.sh multi 233

# 第二步：前端创建 catdog 单数据集对比任务，获得ID后
./scripts/tc42-case5.sh single 234
# 再创建 nlpcc2013 单数据集对比任务，获得ID后单独查看
./scripts/tc42-case5.sh single 235

# 第三步：前端创建第一轮 catdog 重复任务，获得ID后立即查看
./scripts/tc42-case5.sh repeat 236
# 第二轮获得新ID后，再单独查看第二轮
./scripts/tc42-case5.sh repeat 237
# 后续各轮同样操作，每次填写本轮ID

# 至少五轮结束后，再明确填写这些任务的ID做汇总
./scripts/tc42-case5.sh repeat-summary 236 237 238 239 240
```

这些编号是已经核对的真实历史示例，现场使用刚从前端返回的 ID。`multi` 仅接受三数据集对比任务，`single` 仅接受 catdog 或 nlpcc2013 单数据集对比任务，`repeat` 每次只接受一轮 catdog 任务。每轮查询无需等五轮全部创建；只有 `repeat-summary` 要求至少五个不同任务 ID。

上述阶段也支持参数形式：

```bash
./scripts/tc42-case5.sh --stage multi --task-id 233
./scripts/tc42-case5.sh --stage single --task-id 234
./scripts/tc42-case5.sh --stage repeat --task-id 236
./scripts/tc42-case5.sh --stage repeat-summary --repeat-tasks "236 237 238 239 240"
```

不带参数运行 `tc42-case5.sh` 只显示分步用法，不再自动展示历史多数据集、单数据集和五轮重复任务。可追加 `--log-since 1h`、`--output-dir 目录` 或 `--dry-run`。创建任务前的初始状态仍使用 `tc42-case5.sh --stage before` 单独保存。

## 便于阅读的结果展示

`-h` 与 `df -h` 的含义一致，用于切换查询结果的显示方式。可放在子命令前或后；命令帮助使用 `--help`。

```bash
./scripts/tc42-api.sh tc1 228 -h
./scripts/tc42-api.sh tc2 231 -h
./scripts/tc42-api.sh tc3 7 9 -h
./scripts/tc42-api.sh plan 65 -h
./scripts/tc42-api.sh tc4 -h
./scripts/tc42-api.sh tc5 233 234 235 236 237 238 239 240 -h
./scripts/tc42-api.sh --help
```

此模式按测试用例提取关键证据，不逐项翻译 JSON：

- 集中式、分布式计算：每个数据集一行，展示源节点、计划节点、实际节点、完成状态及输入校验；另列读取量、数据移动耗时和传输、计算起止时间。保留资源不足回退、节点不一致及失败原因。
- 温度与存储：实验组和对照组并排展示温度、阈值对照、当前存储节点、温度更新时间及可用副本数。迁移计划只展示源节点、目标节点、操作及完成状态；历史计划与当前位置分开呈现。
- 安全访问：突出当前用户、目标数据集、访问决定、拒绝原因和短期授权期限。管理员查询会明确标明身份，避免误当成受限用户的结果。
- 数据移动加速比：多个任务合并成表，展示 T1、T2、复算 S 及判定，相同路径合并展示；多数据集任务保留逐数据集的累计计时依据。

成功响应中的请求追踪编号、响应码、空字段、容器名称、完整校验字符串和重复的候选节点事件不进入摘要。输入校验显示是否与登记值一致；完整校验字符串仍保留在 JSON 中。缺少模式、读取量、起止时间或输入校验，出现未完成重试、累计计时不一致等情况时，加速比标为“不纳入判定”并说明原因。

容量按 1024 进制换算，计时表统一使用秒。摘要额外查询数据集目录、节点目录等信息以显示名称及核对校验值；这些辅助查询失败时会明确提示，缺少的证据不会补成成功结果。

加速比表按大纲统一使用 T1 表示集中式时间、T2 表示分布式时间，对应原始任务字段 t2、t1，避免历史字段命名造成混淆。不带 `-h` 时仍输出完整 JSON；`--raw` 保留响应原始字节，不能与 `-h` 同时使用。单位换算只影响展示，需要准确原值时使用 JSON 输出。

`tc5` 保留原始任务与逐数据集计时事件，不自动给出通过结论。特别注意历史字段命名：前端将任务字段 `t2` 作为大纲中的集中式时间 T1，将 `t1` 作为分布式时间 T2；单位为秒，`rating` 为加速比。执行事件的 `durationMs` 单位为毫秒。不要直接按字段名称把 t1 当成集中式时间。仅在两种模式完成、证据完整且分布式时间大于零时，才能复算集中式时间/分布式时间并判断是否大于 1.2。

已有 `show-tc42-evidence.sh speedup <任务ID...>` 可以查询数据库累计计时及逐数据集事件，交叉核对原始接口结果。

## 保存与退出码

```bash
./scripts/tc42-api.sh --raw task 233 > task-233.json 2> task-233-request.log
./scripts/tc42-api.sh task 233 | tee task-233-display.txt
```

保存单个完整 JSON 时每次只指定一个编号。多个编号会顺序输出多份响应，不合并为数组；`--raw` 不额外插入分隔符。默认缩进模式适合多编号终端展示。日志和响应可能包含敏感业务信息，请在受控目录保存。

退出码 0 表示所有查询 HTTP 成功且业务 code 为 0；1 表示至少一个网络、HTTP、业务或响应格式错误；2 表示参数错误。批量查询中一项失败后仍继续查询后续编号，最终返回 1。错误响应仍完整输出；查询成功不代表测试用例通过。

本地验证：`python3 -m unittest discover -s scripts/tests -p 'test_tc42_api.py'`。
